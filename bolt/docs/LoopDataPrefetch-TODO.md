# 基于 Arm SPE 的 BOLT Loop Data Prefetch：开发 TODO

当前代码已迁移到 LLVM 24 目标仓，复用、去重及验证边界见[迁移记录](LoopDataPrefetch-Migration.md)。下文原仓评估、提交及实验记录保留其历史含义。

本清单以可商用的 Arm SPE 引导循环数据预取方案为交付目标，覆盖二进制变换、profile 数据通路、自动收益决策和运行验证。开发顺序是：完成 M0 正确性基础，建设 P1 的商用直接预取变换引擎，接入 P2 的可靠 SPE 数据闭环与 P3 的自动决策，再按目标负载扩展 P4 的复杂访问能力。

LLVM 24 当前状态见 [8.17](#817-批量与地址访问运行验证及限定扩展2026-11-03)，此前的 X8 活跃性修复及间接预取边界验证见 8.16。下列历史构建和性能结果不替代当前版本验收。

- `mergeAllDependents()` 复现保留原函数算法，以标准容器别名和替代 `MCInst` 运行，输入依赖顺序 `1 → 2 → 3` 得到 `3 → 2 → 1`。

- 周期区间复现抽取当前累计与差分代码；逆序记录 `A_new(100), B(7), A_old(20)` 得到 27，而按字段语义应为 107，见 P0-03。该复现不包含完整函数中的单次分支除零路径。

### 1.2 M0 完成时的实现边界

本节保留 M0 的验收基线。当前 P1 已扩展的支持范围以 [使用文档](LoopDataPrefetch.md) 和 8.6 为准。

M0 完成时支持 AArch64 用户态 ELF 中的 simple function，限定无 CFI、无未知控制流的单基本块、单 latch 循环。只接受 `LDR{BB,HH,W,X,D,Q}roX` 的 X 索引寻址：base 在循环内不变，index 每轮恰有一次不带标志更新的 `ADDXri/SUBXri` 自递推，立即数为正、无立即数移位。W 索引、writeback、间接地址链和跨块定义均跳过。

生成时暂借 base 做地址加减，再精确恢复 base；因此 base 限于 X0～X17，排除 SP、X18、FP、LR 和 callee-saved base，base 与 index 不能相同。不新增普通 load、栈保存、临时块或分支，不复制原有依赖指令，也不改变 NZCV。带 CFI 的函数明确跳过，避免引入临时寄存器状态与展开规则不一致；P1 再扩展活跃性与 CFI 支持。

每个循环最多插入两条 PRFM，地址增量只接受可直接编码的正负 4095 字节范围。原型距离模型保留 `ceil(100 / measured_cycles_per_iteration) + 10`，没有有效周期、回边计数未知或为零时完整跳过；这不是已校准的性能模型。

### 1.3 Profile 输入边界与通路状态

本项目不支持 `no_lbr`，不与 `perf2bolt -nl` 联用；误用会报错。M0 的主要路径是非 `-nl` 的 `perf2bolt` 转换后再运行 `llvm-bolt`。

| 输入路径 | M0 行为 |
| --- | --- |
| 非 `-nl` 的 `perf2bolt --cache-miss=...` → 扩展 fdata → `llvm-bolt --enable-loop-data-prefetch` | 支持；检查事件、计数、函数匹配和 load 指令偏移，再绑定 annotation |
| 普通旧 fdata | 保持可读；不增加预取字段，不据缺失信息生成预取 |
| `llvm-bolt` 直接读取 `perf.data` 并启用预取 | 明确拒绝，要求先运行 `perf2bolt`，不会静默遗漏绑定 |
| 只有 cache-miss、没有对应函数分支记录 | 启用预取时明确拒绝；普通 Lite 查询能识别访存数据，但不制造执行计数 |
| YAML | 启用预取时拒绝该输入；输出无法保留的 cache-miss/cycle 信息会明确警告；SPE 聚合阶段禁止选择 YAML 输出 |
| BAT cache-miss profile | 明确不支持；扩展该入口不作为 P2 完成条件 |
| `no_lbr` 或与 `-nl` 联用 | 明确不支持，不实现预取字段读写或自动转换 |

“有分支记录但没有有效 cycles”不同于 `no_lbr`，前者根据 CFG 和指令成本静态估算每轮周期，并明确标记来源。P1 已实现 profile 驱动入口，缺失有效周期时静态估算，但不放宽 profile 的上述输入边界。

### 1.4 fdata 扩展约定

预取扩展只保留一种格式，头部包含事件、身份及采样参数，不包含版本字段；身份及采样协议约束见 1.5。

普通 fdata 的分支行保持原来的八个字段，`--cache-miss=none` 不输出新增记录。显式采集 cache-miss 时写出包含事件、身份和采样参数的头：

```text
bolt-prefetch llc_miss 11223344 1024 200000001 0 0
1 loop c 1 loop 0 0 15 100 10
7 loop 0 8 10
```

首行事件仅接受 `tlb_miss/l1d_miss/llc_miss`。采集协议要求所选层级的完整 access/miss 合成事件组，使用每条事件贡献一次计数；不支持 miss-only 或改变分母含义的过滤协议。无效事件、缺失或额外协议字段均拒绝；真实 SPE 采集配置的核验见 1.5，不能仅凭文本头证明原始采集正确。

分支行末尾依次为 `mispreds branches cycle_total cycle_samples`；普通 memory 行保持原格式，cache 行末尾为 `misses accesses`。位置偏移使用十六进制，计数使用十进制。`accesses` 是对应 access 事件数，不再额外加上 miss 事件数。候选要求 access 计数非零、miss 不大于 access，且 miss 比例超过阈值；不设置绝对样本数量门槛。

`CycleStats` 保存周期总和与有效区间数：`samples == 0` 表示未知，`samples == -1` 表示溢出等无效统计，二者 total 均为零；`samples > 0, total == 0` 可表示明确的零测量，但不用于除法。跨样本和跨文件按总和/区间数合并。普通 fdata 不接受额外周期字段；扩展分支记录必须同时包含周期总和与有效区间数，读取和合并遵循相同规则。

身份、事件和采样参数一致的预取文件可合并，miss/access、分支/误预测分别求和，周期保留总和和有效权重；禁止与普通 legacy 文件或其他事件类别混合。记录顺序不影响读取，重复记录合并，未消费的未知记录及截断会报错。

### 1.5 P2 的身份与采样协议

当前 `perf2bolt --cache-miss=...` 写出：

```text
bolt-prefetch llc_miss 11223344 1024 200000001 0 0
1 loop c 1 loop 0 0 15 100 10
7 loop 0 8 10
```

头部依次为 magic、事件类别、原始二进制 build-id、SPE 采样周期、config/config1/config2。build-id 为偶数位十六进制，周期为正十进制整数，三个 config 为不带前缀的十六进制。period 是 SPE 采样器的间隔设置，不是 load 延迟或循环周期，不用于推导 D。分支、memory、cache 记录的字段和单位见 1.4；未知周期为 `0 0`，不制造测量。

采样参数由 `perf evlist -v` 读取；要求单个 Arm SPE 事件、固定周期、仅 load 且没有 event/min-latency 过滤，支持时间戳、地址/上下文包及 jitter 的配置位。缺失、频率模式、混合 load/store 或未支持的配置明确拒绝。只解析所选层级完整 access/miss 合成事件组，不能将 miss-only 或改变分母的采集转换成总体 miss rate。

采集时验证原始二进制与 perf.data 的 build-id，禁止用 `--ignore-build-id` 绕过；读取预取扩展时再次校验输入身份。短 build-id 允许 perf 的尾随补零，不接受非零后缀冒充相同身份。合并要求身份、事件、周期及全部 config 一致，仅按已有计数/周期权重累加，不折算不同周期。

CPU、内核、perf 版本、完整命令、负载、窗口、原始数据及采集开销保存在随附实验记录中。延迟、数据 VA 和时间不加入持久化访存统计；不增加直接 perf.data、YAML、BAT 或 `-nl` 入口。完整命令及故障排查见 [使用文档](LoopDataPrefetch.md)。

## 3. P0：修复正确性、崩溃和兼容性

M0 采用 1.2～1.4 的受限支持范围，保留阶段目标，移除无法证明安全的旧变换路径。以下保留 M0 完成时的检查与限制；P1 已解除的边界以第 4 节和 8.6 为准，不能据此推断 M1～M4 已商用交付或存在生产收益。关键测试和完整回归记录见 8.4。

### P0-01：独立启用开关和支持范围

- [x] `--enable-loop-data-prefetch` 默认关闭；`--print-loop-data-prefetch` 仅控制打印。
- [x] 仅在 AArch64、非 instrumentation 流程注册；排除未知控制流、CFI、非单块/单 latch 和不支持的地址形态。
- [x] 显式拒绝 `-nl/no_lbr`、kernel、预取的直接 perf.data 和 YAML 输入，不扩大不支持模式的读写能力。
- [x] `--cache-miss=none` 关闭新增聚合及输出，原有 `mem-loads` 流程保持独立。
- [x] 要求有效分支 profile；不把无 profile 哨兵或零回边计数解释成测量周期，缺失周期使用明确标记的内部默认值。

### P0-02：按 PC 的 miss/access 统计

- [x] 每个样本只对本 PC 增加一次对应计数，移除全局前缀累计。
- [x] 按所选层级精确接收 access/miss 事件；access 合成事件是分母，miss 不重复加入分母。
- [x] SPE 与既有 memory profile 分流；其他事件及无效 PC 不污染计数，功能关闭时只保留原有 `mem-loads` 语义。
- [x] 拒绝非法持久化计数、缺少 access 的 miss 组及计数溢出；候选显式检查分母及 miss 比例。
- [x] 按完整事件组协议处理输入；拒绝无效头部和事件，其他过滤协议不在 M0 支持范围内。

### P0-03：周期区间、除零和缺失值

- [x] 单次出现的分支不计算重复间隔，修复逆序累计端点：`A_new(100), B(7), A_old(20)` 的区间为 107。
- [x] 保存总周期与有效区间数，合并时求和；移除顺序相关的两值平均。
- [x] 区分未知、无效和有效零测量；原始记录缺失周期时不伪造区间，自动距离在本地按循环静态估算周期，不回写 profile。
- [x] 距离计算不再除以未知或零回边计数，平均周期为零时不执行除法。
- [x] 周期溢出使统计失效，未来地址的步长乘法检查溢出及编码范围，不生成异常大偏移。

### P0-04：opcode、操作数和状态检查

- [x] 按 opcode 白名单验证实际 prime 操作数数量、类型、寄存器类别及 shift 标志，不把 annotation 当机器操作数。
- [x] 立即数寻址、W 索引、writeback 等不支持形态完整跳过，不盲目读取 operand 2 为寄存器。
- [x] 先验证 loop/latch 和周期，再访问回边；不再查找可能失效的指令迭代器、空依赖列表或公共前缀。
- [x] 删除旧 `Prefetch/DependentInfo` 未初始化状态，使用局部完整初始化的计划及计数。

### P0-05：消除错误的依赖拓扑合并

- [x] 删除旧 `mergeAllDependents()`、公共前缀和跨迭代静态指针去重路径，不保留错误入度算法的可达调用。
- [x] M0 不合并或复制依赖链，只从已证明的 base/index 递推构建独立算术序列，不引入图排序或新的依赖框架。
- [x] 按原程序顺序规划、逆序提交，所有序列完整恢复 base，因此多候选不会互相留下临时寄存器状态。

原计划中的单链、环和公共前缀测试不再适用于已经删除的算法；P0-10 只验证现存路径的关键行为。未来恢复跨块依赖合并时，由 P4 重新建立相应约束和测试。

### P0-06：依赖闭合与纯算术生成

- [x] 不复制任何原始依赖指令，不新增普通 load/store/call/atomic/barrier。

## 4. P1：完成商用直接循环预取变换引擎

依赖 M0。P1 的交付目标是面向实际生产二进制的完整直接预取变换能力，包含地址与循环分析、寄存器及展开语义、配置接口、诊断、资源控制和验收。单基本块、无 CFI、X0～X17 base 及短立即数限制属于 M0 的实现约束，不能直接作为 P1 的商用完成条件。

商用支持矩阵应明确目标 CPU/ABI、ELF 类型、常见标量/SIMD 寻址和可归约循环形态，覆盖编译器常见输出。SVE/SME、任意指针追逐等能力按明确的产品范围另行验收；`no_lbr/-nl` 继续排除。超出支持矩阵或无法证明安全的候选必须给出可解释的拒绝原因。

实现应复用 BOLT 的 Pass、MCPlusBuilder、数据流及 CFI 接口，按具体问题扩展能力，保持职责清晰。测试聚焦关键边界和可观察行为，复用现有回归，不为每个 helper 重复增加用例。P1 的自动决策使用现有的分析和生成路径；完整 SPE 商用方案还需与 P2、P3 联合验收。

当前工作区实现、支持矩阵、命令和关键回归见 [LoopDataPrefetch.md](LoopDataPrefetch.md)；生产负载尚未提供，不能把 P1 整体标记为商用验收完成。以下按实际完成的代码及验证勾选。

## 6. P3：自动距离、候选选择与收益验收

依赖 M1 和 M2。复用 P1 的合法性、指令构造、资源预算、节流和实验归档，以及 P2 的身份和统计约束。当前工作区已推进内部默认模型驱动的距离预测、预算内排序、受控自动距离实验；当前只处理不依赖实际测试环境和 benchmark 的工程工作，真实硬件、生产负载验收继续暂缓。以下勾选仅表示已有实现和对应工程验证，不代表自动策略已经取得生产收益。

P3 不建设综合评分、置信度或静态带宽预测框架。没有可解释输入时允许不插入；SPE 原始延迟的自动消费按实际字段来源扩展，不为未验证数据新增格式。

### P3-01：明确距离模型输入与公式

- [x] 移除固定延迟 100 和迭代偏移 10，使用内部缺省延迟 200 CPU cycles；当前 generic 子目标尚未接入具体 CPU 的 cache miss 时延模型。
- [x] 优先使用单 latch 循环有效 profile 的周期总和/区间数；缺失、无效、为零或多 latch 有歧义时，按 CFG 路径及 MC 指令调度模型静态估算。
- [x] 按精确均值计算 `D = ceil(Latency * Samples / CycleTotal)`，用足够宽度保留分数并避免乘积溢出；预测超过固定上限 1000 时跳过，不把越界值截断成任意距离。
- [x] 距离统一自动计算，固定上限 1000，超过则跳过；关闭特性开关可禁用预取。预测不会绕过 profile、合法性或资源预算，缺失输入不采用隐含常数 fallback。
- [x] 诊断输出模型的延迟、周期总和、样本数、来源及距离。SPE 采样 period、timestamp 和数据 VA 均不作为延迟或循环周期。

验收：预测距离可由日志重算；静态成本、分支加权、依赖链、常量内层次数、profile 优先级、分数均值、超大乘积和距离上限均有关键回归。该模型生成可检验的候选距离，不能保证收益；profile 周期可能包含原有 stall，调用者应以校准输入或扫描结果确认其适用性。

### P3-02：核对迭代时间来源

验收：迭代时间有可复核来源；无法静态建模时跳过，不使用固定每轮周期。

- [x] 将 `a[index[i]]` 与一步指针追逐分别实现；通过 `--loop-prefetch-indirect` 显式启用新增普通索引读取，默认保持关闭。

- [x] 用 `remaining > D` guard 保护所有新索引 load 和数据 PRFM，余量不足时整个新增访存块跳过。保留原 load 和 writeback，W/X 回绕及 UXTW/SXTW 按原指令处理；不以 PRFM 的异常行为替代索引 load 的边界证明。
- [x] 不构建通用别名分析：循环内 store、调用、提前退出、额外计数器更新或 SP 更新均拒绝。索引缓冲区须为循环期间有效、映射稳定的普通非 volatile/非 atomic 内存；二进制不能自动辨别这些语义，不把该约束宣称为已由反汇编证明。
- [x] guard 保留 NZCV 和原计数器，最多使用两个空闲 caller-saved；所有地址指令、新索引 load、guard、PRFM 及跳转计入原预算，复用 CFG/CFI 维护；统一使用 profile 驱动路径，见 8.13。
- [x] 在 AArch64 Linux 的限定用例上执行零次、短循环、尾部及 guard page/无效未来数据地址验证，覆盖 D=1/4/16、正反向、pre/post-index 和寄存器索引源地址，校验结果及活跃 NZCV。此项只记录运行正确性，模式及性能验收仍遵守下列边界，见 8.16。
- [x] 多块循环限定为 header 到唯一 latch 的直线链；中间块无分叉和额外入口，计数器仅在 latch 更新。从消费者向前最多检查 32 个指令/块切换步骤，并验证跨块源地址未被覆盖；边界运行及拒绝用例见 8.17。
- [ ] 扩展提前退出、分叉/合流、派生索引值和多层间接访问时，分别补齐访问边界、路径、生命周期及并发/内存语义证明。
- [ ] 评估单阶段及多阶段预取，测量索引 load 自身是否成为新瓶颈。

验收：guard page、短循环、最后 D 次迭代和无效未来索引场景不引入原程序不存在的异常；同时有实机收益证据。

### P4-03：支持外层循环批量预取

- [x] 新增显式 `--loop-prefetch-batch`，实际在父循环入口发出整批地址运算及预取；不复制原循环体、不新增普通 load，不复用旧 `IsBatch` 路径，见 8.14。
- [x] 支持“入口 → 单块内层 → 父 latch”的三块、单子循环结构；从同宽 MOVZ 初始化及 SUBS 1/非零回边取得确切正常量 trip count。动态次数、空/条件内层和提前退出拒绝，不用 profile 回边计数比冒充次数。
- [x] 支持 base-only 连续标量/pair 正反向访问；内层自更新按 trip count 加权，父循环其余自更新各计一次，修正原 load 前的地址相位。覆盖未来 D 次直接父循环之后的整段，未知对齐时包含首尾字节，不静态宣称所有请求落在不同缓存行。
- [x] D 明确使用父循环迭代数，自动模型使用父循环有效周期或按已证明的内层次数静态估算。模式不支持时拒绝，不静默退回内层 D；profile 入口有回归。
- [x] 请求数、候选/循环/函数指令和 CFI/活跃性机制共用；批量计划按父循环共享预算。新增 `--loop-prefetch-batch-max-bytes`，默认按每父迭代 256 个请求行字节计费，不当作真实 cache 容量模型；资源不足拒绝完整计划，不裁掉末端范围。
- [x] 支持父入口通过一次 64 位 MOV 从行基址设置内层遍历指针；以行基址的父迭代递推计算提前量，保留内层地址相位。部分覆盖、重复复制、内存读取及其他行指针重建拒绝，见 8.17。
- [ ] 扩展动态 trip count、端指针比较、其他行指针重建、非连续/索引访问、多个子循环或复杂提前退出时，补齐相应合法性与成本规则。
- [x] 在 AArch64 Linux 限定用例上完成零次、短循环、正反向、pair、不同缓存行对齐及 guard page 边界结果检查；在新增 PRFM/PRFUM PC 通过信号上下文展开检查 CFI，见 8.17。
- [ ] 在目标负载上比较仅在内层预取的基线并证明收益；运行正确性和静态验证不能代替性能验收。

验收：限定支持矩阵下能从指令和诊断重算未来父循环、范围及预算，不产生新增普通 load；运行与收益验收继续独立保留，见 8.14。

### P4-04：一步指针追逐及其他扩展

- [x] 对 `ldr x0, [x0, #offset]` 这类普通 64 位 load，在 D=1 时于原 load 后复用已加载的 next 指针，预取下一轮同一字段；要求该 load 为 base 唯一循环内写入并支配全部 latch，不新增普通 load。

### 8.4 M0 完整收敛记录

当前实现保留 1.2 的受限路径。旧依赖合并、跨块复制和新增 CFG/栈保存代码已移除，未通过添加通用依赖框架或回滚机制扩大实现。P0-05/P0-07 的完成方式是删除不安全路径、使用独立计划和不改变 CFG 的生成方式；不表示旧算法已被修好后重新启用。

M0 仅增加两个 lit 文件（`AArch64/loop-data-prefetch.s`、`X86/prefetch-profile.test`），以及三个单元测试定义：按 PC/事件统计、完整分支样本解析、周期元数据；最后一个按既有 Core fixture 在两个架构上实例化。继续复用首批测试和既有 BOLT 回归，没有为已删除的拓扑/回滚代码补测试。

- 正反向循环分别生成一条 PRFM，反汇编检查正确的移位、正负偏移及 base 恢复；在 AArch64 本机运行原程序和优化程序，检查结果、index 与 base 保持一致。

- 新格式按不同样本权重合并，拒绝事件不兼容、截断和无效头部；普通旧 fdata 回归继续执行。
- successor 复制/移动及替换分别验证保留或失效策略，周期求和溢出进入无效状态。

### 8.8 P3 距离预测、预算排序与全局扫描

- 自动模型使用 `ceil(Latency * Samples / CycleTotal)`，不叠加固定迭代偏移。当前内部缺省延迟为 200 cycles；每轮周期优先使用有效单 latch profile，缺失或不能可靠推导时按 CFG 和 MC 指令调度模型静态估算，并标记来源。
- 使用宽整数计算 `ceil(Latency * Samples / CycleTotal)`，保留分数均值且不溢出乘积；预测超过显式最大距离时拒绝。全局手工距离优先于自动预测，可独立使用并以 D=0 关闭。

- 增加可选最少 miss 样本门槛；诊断补齐模型输入、来源、范围和门槛原因，汇总完整计划、接受 load、请求及新增指令预算数。miss 数只是同协议下的优先级代理，不是 stall 或收益的预测值。

### 8.14 P4-03：常量内层循环的父循环批量预取（当前工作区）

继续在 P4 未提交改动上推进。新增 `--loop-prefetch-batch`，要求显式非零缓存行大小，且父循环仅有入口、单块常量内层及 latch。内层由同宽 MOVZ 正值初始化、SUBS 1 和非零回边执行，计数器无其他定义；未知次数、空/条件内层和提前退出拒绝。

- 每个父循环入口在进入内层之前发出一批 PRFM/PRFUM 和必要地址算术。原内层 load、计数器及回边不移动，内层回边直接回原 load，不重复执行整批。未来地址基于父迭代步长：内层自更新乘确切 trip count，父入口/latch 的更新各计一次，再补上原 load 前的相位和反向范围偏移。
- 连续标量/pair 的内层净步进绝对值须等于实际读取宽度。将 `N * width` 范围按指定缓存行覆盖，包含首尾字节以处理未知对齐；可能向同一实际行发出不同地址的提示，按最坏请求数计费。缺少任何编码、寄存器或预算时拒绝整批。
- 每批仍先生成完整计划；按实际父入口的活跃性选择临时寄存器，原始内层 load 保留为 profile/诊断来源。源指令与插入位置分别记录，支持同一父入口的多批按原序提交。

LLVM 24 断言开启构建通过，Core 为 74 通过、80 按架构跳过，Profile 为 53 全部通过；AArch64、binary-analysis 及所选 profile/merge/SPE/X86 兼容回归为 187 通过、5 项 Unsupported。合成 profile 三组通路及身份/缺周期反例通过；临时禁用两处多块 guard 后运行发生 SIGSEGV。日志、CFI 静态输出、反向验证及修改前快照保存在 `/tmp/bolt-prefetch-extensions-20261103/`。这些结果只验收上述限定能力的正确性；动态内层次数、复杂分叉/合流、多层间接、真实 SPE、生产性能及独立输入验收继续保留未完成。LLVM 24 断言关闭构建和完整 `check-bolt` 不在本轮范围。

## 9. 性能实验记录要求

每组实验至少保存以下信息，建议随实验脚本生成机器可读结果及简短 Markdown 说明。

| 记录项 | 内容 |
| --- | --- |
| 工具与程序身份 | BOLT revision、编译器版本、原始二进制 build-id、三个基线二进制身份 |
| 构建与优化参数 | 优化等级、链接重定位选项、普通 BOLT 参数、预取参数 |
| 硬件和运行条件 | CPU、cache、NUMA、内核、perf、频率策略、CPU 绑定、线程数 |
| 输入与采集条件 | 数据规模、访问分布、随机种子、采样周期、过滤和丢样信息 |
| 变换结果 | 原始 PC、循环、地址表达式、步长、D、字节偏移、hint、插入指令数 |
| 主测量 | 重复次数、每次运行时间或吞吐、分布、误差和相对普通 BOLT 的收益 |
| 辅助指标 | cycles、instructions、适用 cache/TLB 事件、带宽及采集方法 |
| 完整性 | 程序结果校验、失败和退化配置、未匹配 profile 和未支持候选 |

不能只报告“插入了 N 条预取”或“miss 降低了 X%”。验收需要证明程序结果正确、目标 load 被正确处理，且运行时间或吞吐改善可重复。
